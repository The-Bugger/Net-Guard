System Architecture
Component Descriptions

Capture Engine

Lives on the wire via Scapy. Decodes TCP, UDP, ICMP, and ARP packets into a normalised internal format and hands them off to the Detection Engine. Runs in a daemon thread with clean start/stop semantics.

backend/capture/

Detection Engine

Feeds decoded packets through parallel detection rules — SYN Flood, Port Scan, SQL Injection, Brute Force, XSS, SSH Login, Suspicious DNS, Malware Download, and Privilege Escalation. Enforces per-IP cooldowns and sliding time windows. Persists ThreatEvent records to SQLite.

backend/engines/detection/

Explainability Engine

Converts every ThreatEvent into non-expert-friendly text: what happened, why it matters, and what to do. Supports stub (offline), Gemini, and OpenAI providers selectable via AI_PROVIDER env var. Includes a 100-entry LRU cache to avoid duplicate API calls.

backend/services/ai_explain_service.py

Prevention Engine

Applies iptables DROP rules for blocking malicious IPs. Checks the whitelist before any block. Auto-expires blocks after a configurable duration via a background expiry thread.

backend/engines/prevention/

Flask API

20+ REST endpoints for monitoring, detections, blocks, whitelist, statistics, logs, settings, analytics, export (JSON/CSV/Markdown), and AI explanations. Flask-SocketIO pushes new_threat, ip_blocked, and ip_unblocked events to connected clients in real time. Rate-limited (120 req/60 s) with security headers on every response.

backend/routes/ · backend/api/

Frontend Dashboard

Vanilla JS ES6 + Chart.js dashboard. Real-time KPI cards (threats, blocked IPs, health score, detection accuracy), live traffic graph, severity doughnut, activity feed, and management pages for blocks, whitelist, logs, rules, analytics, and settings. Zero build step — no bundler required.

How It Works
  1. 1

    Packet Capture

    The Capture Engine uses Scapy to listen promiscuously on the network interface. Each raw frame is parsed into a normalised dict containing source/destination IP and port, protocol, flags, and raw payload — then placed on an internal queue.

  2. 2

    Threat Detection

    The Detection Engine dequeues packets and evaluates them against nine rule modules. Each rule maintains a per-IP sliding window or state table. When a threshold is crossed, the rule emits a ThreatEvent with an assigned severity (Low → Critical) and confidence score (0–100).

  3. 3

    AI-Powered Explanation

    Every ThreatEvent is passed to the Explainability Engine. In stub mode it generates a detailed Markdown report instantly from a template. When AI_PROVIDER=gemini or openai is set, the live model enriches the report with MITRE ATT&CK mappings, CVE references, business impact analysis, and remediation steps. Responses are cached in a 100-entry LRU to avoid duplicate API calls.

  4. 4

    Automated Prevention

    The Prevention Engine receives the enriched event and, for high/critical severity threats, inserts an iptables DROP rule for the source IP. Whitelisted IPs are never blocked. All blocks are timestamped and auto-expire after the configured duration.

  5. 5

    Persistence & Real-time Push

    The event is persisted to SQLite via SQLAlchemy. Simultaneously the Flask API emits a new_threat SocketIO event to all connected browser clients, giving sub-second dashboard updates without polling.

  6. 6

    Dashboard & Analytics

    The Frontend receives the live push and updates KPI cards with an animated count-up, prepends an entry to the activity feed, and refreshes severity counts. Analysts can also drill into the full detection list with search and pagination, view per-event timelines (/timeline?event_id=…), and export data as JSON/CSV/Markdown.
